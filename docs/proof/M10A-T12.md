## Delivered local application boundary

`run.desen.starter.web@0.7.0#web-react` Catalog. The current Catalog has 32 declared components;
its inert `catalog.json` is 4,120,610 bytes at
`sha256:aa8e9fb01fed930a7f56cd09cf7328e6a49ffa556c4fe80571b5454dd24f87b6`.

The App derives a Catalog inspector lazily only after an exact validator-admitted component
selection; normal canvas and library startup do not eagerly derive the inspector schema matrix.
Its visual controls are typed rather than raw CSS, JSX, or JSON. The closed visual profile admits
only declared layout sizing, solid and gradient fills, borders, radii, shadows, typography, and
supported positioning/transform values. A property can use an explicitly compatible resolved token
or a typed literal, and the UI discloses reset/inheritance rather than silently dropping an edit.
Unsupported, malformed, unsafe, dynamic, or token-incompatible values fail closed.

Desktop, tablet, and mobile use bounded App-owned preview frames. Responsive node overrides are
created, edited, and removed in their declared desktop → tablet → mobile order; a malformed or
non-monotonic cascade is rejected. The normal starter aggregate persists through its dedicated
generation-fenced project-workspace record, not the older Source route. Two independently selected
components receive distinct visual presentations through ordinary product controls, then survive
the focused browser reload observation.

T12 does not add named-theme CRUD, named-theme switching or persistence management, arbitrary
CSS/JSX/JSON authoring, private capability-DOM inspection, Runtime activation, Publisher authority,
Core/protocol changes, G10A, or M11 behavior.
