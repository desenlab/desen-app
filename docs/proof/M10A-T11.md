# M10A-T11 — Direct-manipulation canvas

**Status:** `DONE` — exact-head hosted Quality and fresh-`main` closure are recorded
below.

## Delivered local application boundary

T11 adds an App-owned direct-manipulation layer around the current authored Source tree. It
re-authorizes one bounded multi-selection from exact current route, Source identity, and tree order;
stale, duplicate, cross-route, forged, and over-limit selections are rejected as a whole. A selected
group moves or reorders in one stable-order transaction only when the prospective Source satisfies
the existing slot acceptance, required-slot, cardinality, depth, identity, and cycle rules. A failed
member never permits a valid prefix to mutate Source.

The Design canvas also owns bounded, inert pan/zoom and preview-frame state. Its controls are
accessible App chrome outside the adapter-managed subtree, use no native transfer payload as
authority, and do not write canvas geometry or viewport state into Source. T12 retains authored
visual/responsive editing; T14 retains undo/redo, duplication, and copy/paste.

T11 does not change the DESEN protocol, Runtime Core, Publisher, Catalog public contract, G10A, or
M11 authority.

The suite covers inert bounded viewport/frame state, source-derived multi-selection, modifier
selection limits, accessible canvas controls, native-drag and keyboard placement, stable layer order,
large-tree placement, and atomic rejection of invalid destination, cycle, required-slot, or cardinality
transitions. The reviewed proof-reader successor rebuilds the reachable Vite graph and permits only
the declared T11/T10 back-projections when authenticating frozen M10 evidence; historical artifacts
remain byte-identical rather than being silently regenerated.
