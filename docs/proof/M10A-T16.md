# M10A-T16 — Variants and visual states

Status: `IN_PROGRESS` — local implementation and regression evidence are complete; hosted
exact-head and fresh-`main` closure are still required.

## Boundary

T16 adds the App-owned design-time surface for named component variants and declared visual
states. The boundary uses the existing Editor Core ordered-variant commands and the frozen DESEN
0.1.0 `variants` shape. A named preset is recorded as an inert, versioned extension marker plus a
declared primitive state-axis predicate. Variant edits can change only declared style leaves;
children, slots, behavior wiring and arbitrary predicates are never accepted by this surface.

The Inspector now exposes a `Variants` view beside the existing property, Style, State and Actions
views. The Style view exposes declared visual states and named variant layers. State and variant
layers can be promoted into a transient preview document for the canvas; the authored Source and
its conditions remain unchanged until an ordinary Save source operation.

## Implementation evidence

- `apps/desen-app/src/authoring-variants.ts` projects and validates named variants, primitive state
  axes, versioned metadata and atomic create/rename/delete operations.
- `apps/desen-app/src/variants-panel.tsx` provides the closed named-variant authoring surface.
- `apps/desen-app/src/authoring-styles.ts` and `style-panel.tsx` add declared visual-state and
  named-variant style leaves plus fail-closed transient forced preview.
- `apps/desen-app/src/application.tsx` commits all edits through the existing authoring session
  and preview boundary; no Runtime Core, Publisher or protocol bytes changed.

## Explicit non-claims

T16 does not add Runtime macros, Publisher activation, library release/adoption, Connections,
business actions, arbitrary child replacement through variants, or changes to the frozen protocol,
Runtime Core or M10/G10 authority. Per-instance visual edits remain subject to the existing
T15 master/instance and Source-save boundaries.
