# DESEN 0.1.0 Schema-Derived Type Evidence

## Result

`M02-T03` passes. Three internal TypeScript root declarations are deterministically derived from
the three checksum-protected DESEN 0.1.0 JSON Schema roots, and the package exposes three curated,
documented aliases: `DesenSource`, `DesenBundle`, and `DesenCatalog`.

validation, semantic correctness, official-suite parity, or complete representation of all 989

## Reproducible method

1. The full frozen snapshot is verified before any generation.
2. The exact three schema names, `$id` values, titles, and root names are checked.
3. A generation-only in-memory clone receives five reviewed structural projections:
   - two Source/Bundle predicate `if/then` cardinality refinements are omitted because they belong
     to semantic validation;
   - two Source/Bundle Variant `anyOf(required ...)` rules are distributed over their shared object
     shape; and
   - one Catalog behavior-attachment `anyOf(required ...)` rule is distributed the same way.
4. The full schema roots, including all `$defs`, are compiled independently with
   `json-schema-to-typescript` 15.0.4 and Prettier 3.9.6. External reference resolution, runtime
   enums, and `any` output are disabled.
5. The curated public aliases recursively narrow unconstrained generator positions to
   JSON-compatible TypeScript values.
6. Two independent generations must be byte-identical.
7. The read-only verifier compares the exact output inventory, every generated byte, and the
   deterministic evidence artifact.

The logical distribution in step 3 preserves `base AND (required A OR required B)` as
`(base AND required A) OR (base AND required B)`. The conditional predicate omission is not an
equivalence claim; it is an explicit boundary because TypeScript cannot enforce operator-specific
array cardinality reliably.

## Automated evidence

`pnpm test:protocol-types` covers:

- pristine generation and two-run determinism;
- recursive `ValueSpec[]` preservation and the historical `undefined[]` failure mode;
- closed predicate, required Variant branch, and required behavior attachment structure;
- stale output after an in-memory schema change;
- wrong schema inventory, `$id`, and projection shape;
- changed, missing, extra, and symlinked generated outputs;
- refusal to write through a symlinked output or evidence directory chain;
- stale or modified evidence; and
- the exact three-type public API.

The package's strict TypeScript fixture additionally accepts minimal Source, Bundle, and Catalog
documents plus all seven action discriminants. It rejects wrong document discriminants, missing
required roots, recursive `undefined`, unknown predicate properties, empty Variants, empty behavior
targets, an unknown action kind, executable function data, and a Bundle catalog requirement without
its exact digest.

## Limitations

TypeScript does not replace JSON Schema. In particular, these declarations do not prove patterns,
formats, unique items, property-name rules, general numeric/string/array/object cardinalities,
`oneOf` exclusivity, predicate argument counts, cross-document references, digest correctness, or
every `additionalProperties` interaction. Defaults remain annotations and are never applied by type
generation.

The public aliases exclude functions, `undefined`, `bigint`, and symbols from unconstrained
positions. TypeScript still cannot distinguish finite JSON numbers from `NaN` or infinity.

Those behaviors remain assigned to validator and semantic tasks. No Proof Matrix `P-*` status
changes in `M02-T03`.
