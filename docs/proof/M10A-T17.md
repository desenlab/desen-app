## Delivered boundary

T17 adds an App-owned Design System area generated from the admitted Catalog and current Source.
It provides a searchable component gallery, deterministic foundation scales, usage guidance,
schema-derived props, slots, style parts, declared events/commands, visual states and inert
scenario examples. The area is a documentation and authoring aid; it does not create a second
component registry or a handwritten Storybook story tree.

Catalog and Source mismatches fail closed and are visible to the user. Missing runtime adapters
are reported as `missing`; documentation remains data-only and never executes Catalog-provided
scripts, callbacks or components. Scenario props are transient display data and do not mutate the
authored Source. Existing Design, Run, persistence and frozen protocol boundaries remain intact.

## Delivered boundary

T18 adds a local-first library-management view to the existing Design System area. Each installed
package has an exact immutable release identity, a local usage index, and a deterministic impact
comparison. Designers can explicitly adopt a candidate, reject it, restore a prior release, or
leave the current release unchanged. Deprecated components expose a reviewed replacement when one
exists; no implicit propagation or destructive update is performed.

The view fails closed on unknown packages, malformed releases, missing usage records, ambiguous
replacement candidates, and stale comparison inputs. Usage and impact data are derived from the
current local document only; no remote registry, runtime activation, Publisher mutation or
protocol/Core authority is introduced.
