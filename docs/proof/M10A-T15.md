## Delivered authoring boundary

The version-2 editable-project record adds an explicit bounded recipe graph. Version 1 imports
losslessly with an empty graph; its old inert recipe metadata is never reinterpreted as executable
definitions. The public platform-neutral Core API admits definitions, nested occurrences, stable
identity mappings and explicit overrides. Whole-graph admission includes unused definitions and
requires managed regions to materialize to the stored ordinary DESEN Source exactly.

Capture, create/update/delete, insert, override/reset/detach and ordinary Source reconciliation
are immutable whole-project transactions. Expected project and transitive definition digests
reject stale work. Two-pass qualified identities retain conceptual nodes and wiring across
nested composition; only schema-owned references are remapped, while literal strings and opaque
extensions remain unchanged. Recursive definitions, conflicting structure, cross-occurrence
binding borrowing, unknown capabilities and finite-limit overflow reject without partial state.
Detach removes metadata without changing Source; fresh-ID copies are explicitly detached.

The normal DESEN Neutral App uses one aggregate controller for Source, recipe metadata, history,
preview, dirty state and generation-fenced persistence. Its existing Components pane offers
My components, capture/insert, reset/detach and Edit master. Master editing uses the SAME existing
Inspector, Style and composition tools, with a small Apply/Discard banner. The isolated draft
has its own undo/redo and cannot Save, Open, navigate or Run/Publish. Apply validates the eventual
complete live project and records one live transaction; Discard preserves that project.

The lifecycle rejects incoherent generations and stale/reentrant/disposed completion. An uncertain
write cannot be cleared by discard or retried as a clean save. Existing Account/Flow Source-only
profiles retain their old authority; Publisher and Runtime never interpret the recipe graph.
