# M10A-T13 — Safe local image, icon and font assets

**Status:** `DONE` — exact-head hosted and fresh-`main` closure are recorded below.

## Delivered boundary

T13 introduces the platform-neutral `@desen/design-system-assets` package. Its admission boundary
accepts bounded PNG/JPEG/WebP images, restricted inert SVG icons and WOFF2 fonts. It checks declared
media type against binary magic, validates dimensions from image headers, rejects truncated/corrupt
headers, active SVG/HTML content, external references, absolute/traversal source names and digest
mismatches, then returns an opaque `desen-asset-<sha256>` handle. Asset bytes are detached and held
separately from the project metadata.

The package provides an immutable content-addressed store port, a deterministic in-memory adapter
for tests, inert `extensions["desen.asset"]` project metadata, and bounded image `fit`/normalized
crop data. No URL, path, CSS expression, loader, script or network destination can enter these
contracts. A forged store record cannot be written because the adapter recomputes the digest and
handle from the exact bytes.

The normal App owns browser storage through an IndexedDB CAS adapter in
`apps/desen-app/src/design-system-asset-storage.ts`. It returns an explicit `MISSING_ASSET` or
`CORRUPT_ASSET` diagnostic and never selects a remote fallback. The App bundles
`@fontsource-variable/inter@5.3.0` under `OFL-1.1` for DESEN Neutral, so opening the local product
does not require a remote font request.

T13 deliberately does not change the frozen protocol, Runtime Core, Publisher, release activation,
project schema top-level fields, or visual-capture/acceptance authorities. Font readiness is a
future capture prerequisite; T24 owns hermetic capture and T26 owns acceptance budgets.
